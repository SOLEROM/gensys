# 15_firefox/ — bookmark backup/restore (data is git-ignored, personal)

## Purpose

Carry Firefox bookmarks from the old station to the new one. The *scripts*
are tracked in this repo; the *exported bookmark data* is not — it's
personal browsing data, not something to upload to a git remote.

```
15_firefox/
  export_bookmarks.py   # stdlib-only converter: mozlz4/sqlite -> Netscape bookmarks.html (tracked)
  backup.sh             # run on THIS station: snapshot all profiles' bookmarks (tracked)
  restore.sh             # run on the NEW station: stage the snapshot for import (tracked)
  bookmarks/             # generated by backup.sh — git-ignored, see .gitignore (NOT tracked)
```

## Why the data is git-ignored

Same reasoning as `secrets/`, different sensitivity level: this isn't
credentials, but it *is* a record of everything you've bookmarked —
personal enough that it shouldn't sit in this repo's git history (which may
end up pushed to a remote). `.gitignore` excludes `/15_firefox/bookmarks/*`;
only the three scripts above are ever committed.

## How the data actually moves to the new station, then

The same way as `secrets/`: manually, alongside the rest of this repo's
*working tree* (not via `git push`/`git pull`) — encrypted USB, `scp` over
the existing Tailscale net, etc. `backup.sh` is safe to re-run right before
the actual migration to catch anything bookmarked since the last run.

## Apply

```bash
# on the OLD station, any time before migrating:
./15_firefox/backup.sh

# carry the whole 15_firefox/bookmarks/ folder to the new station out of band
# (it won't come along via git clone/pull — see above)

# on the NEW station, after Firefox has run once (creates a default profile):
./15_firefox/restore.sh
```

`restore.sh` stages the saved backup where Firefox's own
*Library → Import and Backup → Restore* (or *Import Bookmarks from HTML* as
a fallback) can pick it up — that last click is unavoidably manual, Firefox
has no scripted non-interactive bookmarks-import path.

## Not handled here

Browser extensions, saved logins, and open tabs/sessions — a different
problem (extensions sync via a Firefox Account if signed in; logins are in
an encrypted `logins.json`/`key4.db` pair). This folder is bookmarks only.
